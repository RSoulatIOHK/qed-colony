# Network outage recovery

The supervisor treats recognized transient Git and GitHub connectivity failures as retryable controller state. It stores `phase=waiting_network`, the phase to resume, retry count, delay, and UTC epoch retry time in the existing cycle record. The schedule doubles from five seconds up to fifteen minutes by default; policy keys `network_backoff_base_seconds` and `network_backoff_max_seconds` may bound it further. Restart preserves the same cycle, branch, head, PR, review, and retry deadline.

When the deadline arrives, the supervisor probes GitHub and resumes the saved phase. Publication persists the previously published controller SHA before replacing the local candidate head. It accepts only that prior remote SHA or the already-pushed new candidate. An exact Git `--force-with-lease` guard protects each push, including an absent new branch; unrelated remote movement requires attention. It then discovers an existing PR before creating one. Review comments use a cycle/head marker discovered across all comment pages. CI retries fetch the current PR and check rollup. Merge retries fetch the PR before issuing a merge, and the merge uses GitHub's exact reviewed-head guard. These checks make a remote success followed by a lost local response recoverable without creating another PR or merge. Empty-queue planner calls use a durable planner cycle and resume it after the same backoff.

Authentication and authorization errors, invalid candidates, governance handoffs, exhausted daily budgets, and interrupted or uncertain model attempts remain explicit attention or budget states. Provider connectivity failures do not change author revision or reviewer tier; each failed model attempt still consumes its attempt and actual runtime charge, and the retry receives a distinct durable stage ID. Local subprocess timeouts remain explicit failures; only remote broker operations are classified as network waits. Interrupted or uncertain model processes take precedence over network-looking summaries and retain their full runtime reservation. If process cleanup cannot verify termination, the process record and a non-expiring `uncertain` worker slot remain. That slot occupies the existing concurrency allocation until restart cleanup verifies termination; expiry alone cannot authorize another worker. These outcomes require review rather than automatic relaunch. A waiting cycle resumes only after the stored backoff expires and its remote operation can be reconciled.

A provider outage also records `provider_network_offline`, `provider_network_retry_count`, and `provider_next_retry_at` on its originating cycle. Every model stage checks those durable markers before reserving a call, so another cycle or a restarted controller cannot bypass known provider downtime. After bounded backoff, a credential-free HTTPS `HEAD` request to the Codex provider endpoint has a five-second timeout. DNS, connection and server failures extend backoff without a model attempt. A reachable endpoint clears the guard; authentication or method responses establish reachability only, and do not certify the worker's credentials, subscription, or backend inference health. Actual CLI provider error events retain a safe connectivity/authentication classification while raw error details remain in private logs.

The reachability probe currently targets the ChatGPT-backed Codex endpoint. Custom Codex providers require a separately reviewed probe adaptation. The public API omits private cycle data; inspect local persisted cycle state for these detailed recovery fields.

## Operator steps

1. Inspect the cycle phase, `resume_phase`, `network_retry_count`, and `next_retry_at` in controller state.
2. Restore network access. The supervisor polls automatically and retries after the recorded deadline.
3. If the state becomes `needs_review`, inspect its `last_error`; authentication, candidate, and uncertain-process failures require explicit operator handling.
4. For `budget_limited`, wait for the configured daily reset. Do not clear attempt reservations to force a retry.
5. SRE governance candidates that reach `awaiting_controller_integration` still require independent controller integration and deployment.

The supervisor requires no operator command to resume: keep it running and it probes on the regular poll after `next_retry_at`. A restart reads the same SQLite cycle state. If a process attempt is recorded as interrupted, do not reset it or start a replacement until its outcome is reconciled.

The classifier is deliberately narrow and matches common subprocess messages. Unknown failures remain attention errors. This local controller state is operational recovery, not a security boundary.

## Validation and failed experiments

The original bounded implementation timed out before a reviewable handoff. It preserved useful fault tests but rejected normal publication revisions and could not restart a planner whose initial worktree fetch failed. Those paths now have explicit prior-head lease and queued-planner restart regressions. An initial fake-executor-only check also missed the CLI adapter's generic error summary; tests now execute a fake CLI emitting real `turn.failed` and `error` event shapes, covering safe network/authentication classification and the full pipeline boundary. Process uncertainty and expired-slot regressions verify that ambiguous termination cannot be converted into an offline retry. A fault using the real GitHub CLI also exposed its `error connecting to` / internet-connection diagnostic; the remote-only classifier now recognizes that shape and Go/macOS DNS forms while local candidate errors remain distinct.

No benchmark statement, acceptance criterion, controller permission, runtime cap, or model tier changes as part of this implementation. The operator must review the governance PR and passing checks before separately integrating its runtime.
