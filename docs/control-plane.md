# Local control plane

The pilot uses Python 3.9 or newer and its standard library. SQLite in WAL mode
holds tasks, leases, agents, an append-only event log, and recorded measurements.
There are no simulated agents or benchmark successes. The store does not certify
claims: workers must attach the actual logs, revisions, and proof-checking evidence.

## Commands

From the repository root:

```sh
python3 -m colony init
python3 -m colony status
python3 -m colony serve --port 8765
python3 -m colony enqueue research-one "Investigate a proof procedure" --role researcher --priority 10 --acceptance "Publish a reproducible experiment"
python3 -m colony export --output observatory/dist/state.json
python3 -m colony run --once --role researcher --timeout 180
```

`run` performs one bounded worker invocation by default. See the worker's
documentation for model execution, sandboxing, and artifacts. It does not create
an endless background process.

Global `--config PATH` and `--database PATH` options precede the subcommand. Config
paths resolve relative to the configuration file, while explicit command-line
overrides resolve relative to the current directory. `colony.json` accepts:

```json
{
  "database": ".colony/colony.db",
  "seed_file": "tasks/initial.json",
  "observatory_dir": "observatory/dist",
  "project": {
    "name": "QED Colony",
    "repo_url": "https://github.com/RSoulatIOHK/qed-colony",
    "mission": "Local, reproducible verification with kernel-checked proofs."
  }
}
```

The seed is either a task list or an object containing `tasks`. Each task needs
`id`, `title`, and `role`. Optional fields are `priority` (higher runs first),
`depends_on` (task IDs), `acceptance` (criteria), `description`, and `status`
(default `ready`). Running tasks cannot be seeded because they require an owner
lease. Repeating `init` inserts only previously unseen IDs; it never resets work.

## Worker API

```python
from colony.store import Store

store = Store(".colony/colony.db").initialize()
store.seed([{ "id": "experiment", "title": "Run experiment", "role": "researcher" }])
store.register_agent("unique-process-id", "Researcher", "researcher")
task = store.claim("unique-process-id", role="researcher", lease_seconds=300)
if task:
    store.heartbeat(task["id"], "unique-process-id", lease_seconds=300)
    store.transition(task["id"], "review", "unique-process-id",
                     summary="Experiment artifacts are ready for review",
                     branch="codex/experiment",
                     pr_url="https://github.com/owner/repository/pull/123")
```

The URL above is an API illustration, not a project artifact. Supply an actual
URL after creating a PR. A branch or PR is optional for work that has not reached
that stage. URLs are never generated by the store.

Public method signatures:

```text
Store(path)
initialize() -> Store
seed(tasks: list[dict]) -> number of inserted tasks
register_agent(agent_id, name, role) -> agent dict
claim(agent_id, role=None, lease_seconds=300) -> task dict | None
heartbeat(task_id, agent_id, lease_seconds=300) -> task dict
transition(task_id, status, actor, summary="", branch=None, pr_url=None) -> task dict
recover_expired() -> number of recovered leases
get_task(task_id) -> task dict | None
get_agent(agent_id) -> agent dict | None
record_event(kind, actor, message, task_id=None, data=None) -> event ID
record_benchmark(data: dict) -> benchmark ID
record_review(data: dict) -> review ID
snapshot(project=None) -> snapshot dict
```

Register a distinct agent ID for each worker process. A registered agent has at
most one active task. Claims use `BEGIN IMMEDIATE`, so competing processes cannot
claim the same task. A claim requires every dependency to be `done`. Incomplete or
missing dependencies put a ready task in `blocked`; completing them automatically
returns it to `ready`. Explicitly blocked tasks stay blocked until released.
Cycles remain visibly blocked; the pilot has no cycle-breaking policy.

Only the current owner with an unexpired lease can heartbeat or transition a
running task. Heartbeats renew the lease; they do not create a noisy event for
each renewal. The lease duration must be positive and at most 24 hours. Expired
leases are recovered atomically before claims, or explicitly with
`recover_expired()` / `status`. Snapshot reads and HTTP reads do not mutate state.
A disconnected worker must stop modifying work once its lease expires.

Transitions are:

| Current | Allowed next states |
|---|---|
| ready | blocked, failed (running only through a claim) |
| running | ready, review, blocked, done, failed |
| review | ready, done, blocked, failed |
| blocked | ready, failed |
| failed | ready, blocked |
| done | terminal |

A same-state transition is a no-op. Lease ownership still applies to running
tasks. Review approval is explicit (`review -> done`); creating a PR alone does
not complete a task. Authorization of reviewers and proof gates belongs to the
worker/merge policy, not this local store.

`record_benchmark` and `record_review` store the supplied JSON objects with an
assigned `id` and UTC `at` timestamp. Useful benchmark fields include `name`,
`task_id`, `actor`, `commit`, `command`, `result`, `elapsed_seconds`, and an
artifact URL. Useful review fields include `task_id`, `actor`, `pr_url`, `verdict`,
and `summary`. No result is inferred merely because a command ran. The schema is
deliberately open while the evaluation contract is established.

## Observatory API and export

`GET /api/state` returns schema version 1 with `project`, `generated_at`,
`mode: "live"`, `agents`, `tasks`, `events`, `benchmarks`, and `reviews`. Timestamps
are ISO 8601 UTC. Task objects include ownership and lease expiry; events include
`id`, `at`, `kind`, `actor`, `task_id`, `message`, and `data`. Events are ordered by
their monotonic IDs. Empty benchmark/review arrays mean none have been recorded.

Export writes the same data atomically with `mode: "snapshot"`. Its default
destination is `observatory/dist/state.json`. A published snapshot is a frozen
record, not evidence that the swarm is currently running.

The server binds to `127.0.0.1` by default. It has no mutation endpoints, directory
listing, filesystem browsing, or database download endpoint. Static assets are
restricted to the configured directory and an allowlist of web file types;
hidden paths, traversal, and symlinks escaping the root are denied. Responses use
`nosniff`, a self-only script policy, frame denial, and no-referrer. API responses
are not cached. Do not put secrets in task descriptions, messages, or the static
asset directory.

This is a local pilot, not a hardened multitenant service. SQLite's append-only
triggers prevent accidental SQL updates/deletes through normal clients; anyone
who controls the database file can replace it or remove those triggers. Back up
the database and associated WAL consistently, or stop writers before copying.
The server has no authentication or rate limiting. Public deployment should
serve a reviewed static export or add an appropriate hosting layer.

Run the focused tests with `python3 -m unittest discover -s tests -v`.
