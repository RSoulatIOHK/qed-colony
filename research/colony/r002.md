## R002 research artifact: compiled-contract semantic audit

**Status:** Audit plan only. The existing [R002 proposal](<checkout>/research/colony/r002.md) identifies the main obligations. No compiled-contract correspondence has been established.

| Semantic bridge | Required audit evidence |
|---|---|
| Source → artifact | Immutable validator source, compiler and settings, language version, compiled bytes and digest, serialization mode, and script hash. |
| Artifact → UPLC term | Correct Flat/CBOR decoding and version selection; explicit rejection of malformed inputs. |
| Ledger inputs → `Data` | Correct datum, redeemer, context, and `IsData` encodings, including partial decode behavior. |
| Original term → prepared proposition | Proof that input application and every preprocessing step preserve the relevant execution outcome, or a theorem over the original term. |
| Lean CEK → reference execution | Agreement on evaluation order, errors, builtins, and version-specific semantics; a separate bridge for ledger CPU and memory budgets. |
| Lean context → ledger context | Evidence that validity predicates and transaction fields match the chosen ledger era. |
| Proof → assurance claim | Exact original property and bounds, kernel evidence, and separately recorded replay, conformance, and Cardano correspondence results. |

These are **proof obligations**, not completed proofs. The libraries’ documented import and preparation flow motivates the audit surfaces. [CardanoLedgerApiBlaster documentation](https://github.com/input-output-hk/CardanoLedgerApiBlaster), [PlutusCoreBlaster documentation](https://github.com/input-output-hk/PlutusCoreBlaster).

**Outcomes and non-vacuity.** Classify fuel or budget exhaustion as incomplete, script failure as an explicit evaluation error, and success as an explicit successful result. Keep decode errors separate. For SellNFT, require a valid successful sale, a valid failing sale, an intentionally invalid context rejected by the premise, and a replayable valid multi-satisfaction attack witness. Audit reachable builtins, their costs and edge cases; identify cryptographic implementations and trust assumptions. Differential tests and vectors provide conformance evidence, not universal correctness.

**Initial target:** SellNFT in `Tests/Scripts/SellNFT` is the appropriate candidate because its documented seller-payment properties and multi-satisfaction counterexample give both positive and adversarial cases. [Upstream example](https://github.com/input-output-hk/CardanoLedgerApiBlaster). **It is not yet reproducibly pinned.** I could not verify an immutable upstream commit, exact source file, compiler recipe, language tag, or compiled artifact digest. Those fields remain required before this candidate meets the target acceptance criterion; supplying values from the moving `main` branch would misidentify the artifact.
